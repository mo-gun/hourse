## 1. 정답지를 어떻게 막았나

이게 이 기록의 핵심이다. 사후에 "그날인 척" 예측하려면 미래가 새면 안 된다.

```
원장 456,746행 → rcDate < 20260912 로 절단 (최대 20260910)
중간 개최일 149행 보강 — [20260911]        ← 그날 기준으로 이미 공개된 정보
대상일 156두 · 결과 33필드 제거 · assert 로 확인
남긴 당일값 {wgHr: 156, weather: 156, track: 156}   ← 발주 전에 알 수 있다 (tier B/C)
```

- **자른다** — 대상일 전날까지만 남긴다
- **보강한다** — 그 사이 개최일(9/11·9/12)은 예측 시점에 결과가 나와 있던 경주다. 지우면 오히려 틀린 재현이다
- **지운다** — 대상일의 결과 34필드. 지웠는지 `assert` 로 확인한다. 조용히 새면 결과 전체가 무효다
- **남긴다** — 마체중·날씨·주로. 발주 **전에** 알 수 있는 값이다(마체중 tier=B, T−61분 실측)

출전취소·기수변경도 발주 전 정보라 그대로 반영한다.

## 6. 역배형이 이변을 잡았나 — 아니다

`basemodel/config.py` 의 `UPSET` 은 `"inherit": "BASIC"` 이다.
**축 가중치를 기본형에서 그대로 물려받고, 다른 것은 시장 계수 `m` 하나뿐이다.**
시장 계수는 확정배당을 먹는데 배당은 발주 T−5분에나 생긴다.
→ **주말 실시간에서 역배형 = 기본형.** 이변을 잡을 장치가 없다.

배당을 알았다고 가정하고 사후 재현했다 (`tools/upset_posthoc.py`):

| | 1착 적중 | 픽 평균배당 | 이변 적중 |
|---|---:|---:|---:|
| 기본형 (= 실시간 역배형) | 6/28 | 2.5 | **0/4** |
| 역배형 m=−0.27 (사후) | 7/28 | 3.3 | **0/4** |

| 이변 경주 | 배당 | 기본 순위 | 역배 순위 |
|---|---:|---:|---:|
| 09/12 서울 5R 마이티아미 | 56.9 | 9위 | 8위 ↑ |
| 09/12 서울 2R 툰테자 | 47.2 | 6위 | 6위 = |
| 09/12 서울 10R 마이티조이 | 25.2 | 5위 | 5위 = |
| 09/13 서울 1R 선더마타 | 20.9 | 4위 | 3위 ↑ |

**한 칸씩 올릴 뿐 1위로 못 올린다.** 그리고 대가가 있다:

```
전체 28경주  평균 −0.21위    ← 오히려 내려간다
이변  4경주  평균 +0.50위    ← 여기선 올리지만
평범 24경주  평균 −0.33위    ← 나머지에서 잃는다
```

basemodel README §5 에 이미 실측돼 있던 값과 맞는다 — 역배형 역배 적중 **0.5%**
(기본형 0.2%). **200경주에 1번꼴**이라 28경주 기댓값은 0.14개다. **0/4 는 예상대로다.**

## 7. 이 기록에서 실제로 확인된 것

1. **블라인드 파이프라인이 끝까지 돈다** — 절단·보강·제거+assert, 28경주 268두
2. **정답지 차단이 작동한다** — 9/13 예측 시 9/11·9/12는 보강하고 9/13만 지웠다
3. **성적은 판정 불가** — 세 지표 구간이 기대치를 품고 시장도 같이 낮았다

유의하게 판정하려면 200경주 이상이 필요하고, 그건 `valid` 1,254경주가 이미 하는 일이다.
**주말 28경주는 파이프라인 점검용이지 모델 개선 근거가 아니다.**
