## 1. 무엇이 문제인가

`F6_mkt_rank == 1` 인 **행**을 전부 세면 분모가 부풀려진다. 배당률이 같은 말이 2두 이상이면
rank 가 둘 다 1이 되기 때문이다. train 36,586경주 중 **1,248경주(3.4%)** 가 여기 해당한다.

**`F6_mkt_rank` 자체는 정상이다.** 동률 경주 1,248개를 전수 확인한 결과,
rank=1 인 말들의 `F6_mkt_prob` 가 **100% 서로 같았다**. 표준 min-rank 방식이고 버그가 아니다.
동률의 내역은 두 가지다.

| 유형 | 경주 수 (train) | 내용 |
|---|---:|---|
| 실제 배당 동률 | 911 | 상위 2~3두가 같은 배당 |
| 배당 결측 | 337 | 전 출주마 확률이 균등 → 전원 rank 1 |

문제는 **평가 방식**뿐이다. 실제 베팅에서는 동률이어도 **한 두만** 고르는데,
현재 집계는 동률 말을 전부 세어 적중률을 낮춘다.

---

## 2. 교정 규약 — 동률 시 무작위 1두 선택의 기대값

경주 단위로 집계하고, 동률이면 `1/k` 가중한다.

```
경주 적중 기여 = (rank1 인 말 중 승리한 두수) / (rank1 인 말 두수)
```

동률이 없으면 값이 0 또는 1이라 기존과 동일하다. **표본(경주 수)도 줄지 않는다.**
문헌에서 쓰는 표준 방식이고, "인기 1위마에 건다"는 전략을 그대로 반영한다.

## 5. 왜 발표 전에 고쳐야 하나

교정 전후로 결론이 뒤집힌다.

```
현재 README:  시장 34.2%  vs  인기도 포함 모델 36.8%   →  +2.6%p   "이겼다"로 읽힘
교정 후:      시장 35.6%  vs  인기도 포함 모델 36.8%   →  +1.2%p   표준오차(1.7%p) 안
```

심사에서 "인기1위가 802경주에 857두인 이유"를 질문받으면 방어가 어렵다.
반대로 **먼저 짚고 "그래서 결합 전략으로 간다"고 말하면 데이터를 제대로 봤다는 신호**가 된다.
