결론

#18 애널리스트 리포트 검증 플랫폼 — 예측을 온체인에 박제하고 데이터로 채점한다

자본시장연구원이 25년치 리포트 74만 건을 분석한 결과, 매수 의견이 93.1%인데 목표주가 달성률은 19%였다. 그리고 결정적으로 — 틀린 목표주가는 나중에 조용히 하향 조정된다. 아무도 사후 검증을 하지 않는다.

“이 애널리스트, 실제로 얼마나 맞혔나?” 이 질문에 답하는 서비스가 국내에 없다. 그리고 이 문제는 불변 원장이 아니면 풀리지 않는다 — “왜 블록체인이냐”에 이만큼 깔끔하게 답하는 후보가 나머지 20개 중에 없었다.

덤으로 RAG가 장식이 아니라 데이터 파이프라인 그 자체가 된다. 아래에 실측 근거가 있다.

솔로랭크에 대해서는 맞고, 프로 경기에 대해서는 틀리다

LCS·LEC·LCK는 솔로랭크와 완전히 다른 서버 클러스터에서 운영돼 Riot 공식 API로 조회되지 않는다. LCK 결과는 비공식 esports-api.lolesports.com에서만 나오고, 이 API는 2020년 이후 유지보수가 중단됐으며 Riot은 하위 호환을 보장하지 않는다고 명시했다. 게다가 Riot 개발자 키는 24시간마다 만료되고, Production 키 승인은 최대 한 달이 걸린다.

일정도 정확히 어긋난다

LCK 플레이오프 결승 9월 13일, 롤드컵은 10월 15일 ~ 11월 14일. 7주 프로젝트라면 후반부가 통째로 프로 경기 공백과 겹친다 — 하필 유저 테스트를 돌려야 할 시점에 예측할 경기가 없다.

살리려면 프로 경기 대신 솔로랭크로 틀어야 한다. 공식 API로 항상 데이터가 나오고, “이번 주 우리 반에서 티어 올릴 사람” 같은 형태면 싸피 몰입도까지 얻는다.

문제

애널리스트가 제시하는 목표주가의 투자기간은 통상 6개월에서 1년이다. 예측 → 결과 확정 → 정산 사이클이 프로젝트 기간 안에 한 바퀴도 돌지 않으면, 가장 중요한 데모를 못 보여준다.

해법 · 두 갈래

백테스트 + 단기 이벤트

① 과거 리포트 백테스트 — 2024~2025년 리포트를 수집하면 이미 결과가 난 건들로 애널리스트 적중률 랭킹을 즉시 만들 수 있다. 예측 기능 없이 이것만으로 서비스가 성립하고, 유저가 온다.

② 예측 이벤트는 단기로 — “발간 후 5거래일 수익률 구간”, “30일 내 목표주가 도달 여부”, “다음 실적이 컨센서스를 상회할까”. 이러면 프로젝트 기간에 사이클이 여러 번 돈다.

7주 · 기능단위 + Git flow

1주차 끝에 이미 배포된 것이 있다

W1–2 크롤러 + RAG 추출 파이프라인 → 적중률 랭킹 페이지만 먼저 론칭. 예측 기능 없이도 서비스가 성립한다 유저 테스트 1차
W3–4 예측 이벤트 + 컨트랙트 정산 + 지갑 연결 — 명세의 Factory·PredictionEvent 골격을 얹는다 —
W5 온체인 리포트 해시 기록 + 이의제기 기간 — 블록체인 당위성이 화면에 드러나는 지점 유저 테스트 2차
W6–7 피드백 반영 + 완성도 + 발표 준비 —

기능단위로 잘리는 구조라 Git flow와 6인 병렬 작업에 그대로 맞는다. “빠른 론칭 → 유저 테스트 → 피드백”이라는 도전 과제가 로드맵에 내장돼 있다.

시작 전에

정해두고 넘어가야 할 것

  1. 리포트 PDF 원문은 증권사 저작물이다. 원문을 재배포하지 말고 메타데이터 — 목표주가, 투자의견, 발간일, 애널리스트, 증권사 — 만 추출·저장하고 원문은 출처 링크로 연결한다. 이것만 지키면 리스크가 크게 낮아진다.
  2. 수집 범위를 먼저 확정한다. 과거 몇 년치, 어느 종목군, 어느 증권사까지. 백테스트 랭킹의 신뢰도가 여기서 갈린다.
  3. 추출 스키마를 문서로 고정한다. “어떤 필드를, 어떤 근거 문단과 함께, 어떤 신뢰도로 뽑는가”. 이 문서가 곧 RAG 파이프라인의 명세이자 오라클 확정 기준이 된다.
  4. 단기 이벤트의 확정 규칙을 정한다. 5거래일 수익률 구간인지, 30일 내 목표주가 도달 여부인지. 기준가·시점·구간 폭까지 못 박아야 컨트랙트 설계가 시작된다.
  5. RAG 추출 정확도의 목표치를 세운다. 정규식 베이스라인이 40%다. 이 숫자를 얼마까지 올렸는지가 발표의 핵심 지표가 된다.
