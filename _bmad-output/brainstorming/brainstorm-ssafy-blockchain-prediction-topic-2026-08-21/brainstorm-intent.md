# 브레인스토밍 인텐트 — SSAFY 블록체인 예측 시스템 주제 (2차 · 회의 반영)

> 다운스트림 스킬(`bmad-product-brief`, `bmad-prd`, `bmad-spec`) 입력용.
> 전체 세션 기록은 같은 폴더의 `.memlog.md`.
> 1차 인텐트(데이터 가용성 단일 기준)는 팀 회의에서 조건이 추가되어 이 문서로 대체됨.

## 팀이 확정한 제약

- **목표 배분:** 수상 80% / 취업 20%
- **사용하고 싶은 기술:** RAG
- **방법론:** 기능단위 개발, Git flow
- **도전 과제:** 빠른 론칭 → 유저 테스트 → 피드백
- **팀 구성:** 6인
- **블록체인 당위성 3조건** (팀이 직접 정의):
  1. 운영자를 믿지 않아도 보상금을 맡길 수 있음
  2. 결과 검증자가 거짓말하면 예치금을 잃음
  3. 확정된 결과에 따라 누구도 막을 수 없이 자동 정산됨

## 확정된 방향

**주제:** 애널리스트 리포트 검증 플랫폼 — *예측을 온체인에 박제하고 데이터로 채점한다*

**문제 정의:** 국내 애널리스트 리포트의 매수·적극매수 의견 비중은 93.1%인데
목표주가 실제 달성률은 19%다(자본시장연구원, 25년치 74만 건).
그리고 **틀린 목표주가는 나중에 조용히 하향 조정된다.** 사후 검증을 하는 곳이 없다.

**한 줄:** "이 애널리스트, 실제로 얼마나 맞혔나?" — 이 질문에 답하는 서비스가 국내에 없다.

## 왜 블록체인인가 (팀 3조건 + 1)

| 조건 | 충족 방식 |
|---|---|
| 운영자 불신 하에 보상금 예치 | `PredictionEvent` 컨트랙트가 참여 풀 직접 보관 |
| 검증자 거짓말 시 예치금 상실 | 오라클 리포터 스테이킹 + 이의제기 기간 슬래싱 |
| 막을 수 없는 자동 정산 | 명세서의 비례(parimutuel) 정산 함수 |
| **＋ 틀린 전망의 은폐 방지** | **리포트 스냅샷 해시를 발간 시점에 온체인 기록** |

네 번째가 핵심 논거. 불변 원장이 아니면 풀리지 않는 문제.

## 왜 RAG인가 (실측 근거)

네이버 금융 리서치 리포트 10건 실측(2026-08-21):

- 목록 수집 `HTTP 200`, 페이지당 30건, `nid` 순차 증가 → 과거분 대량 수집 가능
- PDF **10/10 다운로드 + 텍스트 추출 성공** (스캔 이미지 아님)
- **정규식만으로 목표주가 추출은 4/10** — 증권사별 레이아웃 상이, ISSUE COMMENT·NOT RATED·기업분석 혼재
- 주가 조회 `HTTP 200` (네이버 금융 API) → 목표주가 달성 여부 100% 자동 판정

→ **RAG가 챗봇 애드온이 아니라 데이터 파이프라인 그 자체.**
리포트 유형 분류 → 목표주가·투자의견 추출 → 근거 문단 인용까지가 전부 RAG.
**정규식 베이스라인 40%를 얼마까지 올렸는지가 발표의 핵심 지표.**

## 핵심 약점과 해법

**약점:** 목표주가 투자기간은 통상 6~12개월 → 7주 안에 예측→확정→정산 사이클이 안 돈다.

**해법 (두 갈래 병행):**
1. **과거 리포트 백테스트** — 2024~2025년 리포트로 이미 결과가 난 건들의 **애널리스트 적중률 랭킹**을
   즉시 생성. 예측 기능 없이도 서비스가 성립하고 유저 유입이 발생.
2. **단기 예측 이벤트** — "발간 후 5거래일 수익률 구간", "30일 내 목표주가 도달 여부",
   "다음 실적이 컨센서스 상회 여부". 프로젝트 기간에 사이클이 여러 번 돈다.

## 데이터 소스

| 용도 | 소스 | 상태 |
|---|---|---|
| 리포트 목록·PDF | 네이버 금융 리서치, 한경컨센서스 | 실측 200, 크롤링(공식 API 아님) |
| 목표주가·투자의견 추출 | 리포트 PDF → RAG 파이프라인 | 정규식 40% → RAG로 개선 대상 |
| 결과 확정(주가) | 네이버 금융 API | 실측 200, 종가 반환 |
| 보조(선택) | 업비트 Quotation | 무인증 200, 초단기 데모용 |

## 7주 로드맵 (기능단위 + Git flow)

| 주차 | 산출 | 유저 테스트 |
|---|---|---|
| W1–2 | 크롤러 + RAG 추출 파이프라인 → **적중률 랭킹 페이지 선론칭** | 1차 |
| W3–4 | 예측 이벤트 + Factory/PredictionEvent 정산 + 지갑 연결 | — |
| W5 | 온체인 리포트 해시 기록 + 이의제기 기간 | 2차 |
| W6–7 | 피드백 반영 + 완성도 + 발표 | — |

## 명세 고정 제약 (설계 전제)

- 패리뮤추얼 정산 — 전체 풀을 정답 선택지 참여 비율로 분배
- 1인 1이벤트 1참여, 결과 확정 후 참여 차단
- `PredictionEventFactory` → 이벤트별 `PredictionEvent` 배포
- `Ownable` 운영자만 결과 확정, 확정은 1회 불변
- ERC-20 `approve` → `transferFrom`, 기수별 토큰(비환금)
- Besu 21.10.2 (퍼블릭 오라클 네트워크 사용 불가 → 자체 오라클 필수)
- Solidity 0.8.24 · React 17 + TS 5.8 · Node 24 + Express 4 · PostgreSQL 16
- 선택 확장: 수수료율, 추가 배당금, 환불 모드, 잔여 토큰 회수

## 차선책

- **#12 유튜브 조회수 예측 (51점)** — 데이터 최상, 1주 사이클 완벽, 유저 테스트 최용이.
  RAG 당위성 약하고 문제의식 얕음. *완성도로 승부할 때.*
- **#5-1 e스포츠 → 솔로랭크 전환 (46점)** — 유저 확보력 최고, 소재 흔함. 프로 경기 전제 수정 필수.
- **#17 부동산 (45점)** — 실거래 공개가 계약 후 30일이라 사이클이 프로젝트 기간 초과.

## 시작 전 확정 필요

1. **저작권 가드레일** — 리포트 PDF 원문 재배포 금지. 메타데이터(목표주가·투자의견·발간일·애널리스트·증권사)만 저장하고 원문은 출처 링크로 연결
2. **수집 범위** — 과거 몇 년치 / 어느 종목군 / 어느 증권사까지 (백테스트 신뢰도가 여기서 갈림)
3. **추출 스키마** — 필드, 근거 문단, 신뢰도. 이 문서가 곧 RAG 파이프라인 명세이자 오라클 확정 기준
4. **단기 이벤트 확정 규칙** — 기준가·시점·구간 폭까지 명시해야 컨트랙트 설계 착수 가능
5. **RAG 추출 정확도 목표치** — 정규식 베이스라인 40% 대비 목표 수치
