# 경마 기반 AI 예측 플랫폼 — 주제 실현가능성 리서치

**이 리서치가 서비스하는 결정:** SSAFY 6인 7주 블록체인 프로젝트 주제를 경마 기반 AI 예측 플랫폼으로 확정할 것인가.
2026-08-21 브레인스토밍에서 경마는 '사행성 정면' 사유로 배제되고 '애널리스트 리포트 검증'이 확정된 상태이며, 본 리서치는 그 결정을 뒤집을 근거가 있는지를 검증한다.

---

## 총평 (Executive Summary)

**판정: 조건부 부(否). 경마를 프로젝트의 "본체"로 삼는 것은 권하지 않는다. 다만 배제 사유는 8/21에 적었던 "사행성"이 아니다.**

기획서가 세운 데이터 가설은 **대체로 옳았고**, 오히려 기대보다 좋다. 한국마사회 API는 실존하고, 무료이며, **이용허락범위가 "제한 없음"**이고, 3주 전에도 갱신된 현행 API다 [1][4][5]. 개발계정 자동승인 3,000콜/일이면 5년 백필이 6인 분산으로 하루면 끝난다 [3][4]. **데이터는 문제가 아니다.**

**문제는 다른 세 곳에서 나왔다.**

1. **블록체인 당위성이 팀 자신의 3조건을 통과하지 못한다.** 팀이 정의한 조건 2는 "결과 검증자가 거짓말하면 예치금을 잃음"이다. 그런데 경마 결과는 **한국마사회라는 단일 공신력 기관이 확정 발표**한다 — 검증자가 거짓말할 구조적 여지가 없다. 오라클 분쟁이 발생할 수 없는 도메인에서 오라클 스테이킹·슬래싱·이의제기는 장식이 된다. 애널리스트안이 가졌던 "틀린 목표주가가 조용히 하향 조정되는 것을 불변 원장으로 막는다"는 논거에 비해 명백히 약하다. **이것이 가장 무거운 결격 사유다.**

2. **AI 차별화 공간이 이미 닫혀 있다.** 팀 기획의 3축이 각각 실서비스로 존재한다 — 공공데이터 기반 AI 예상 앱 **경마선생**(프리미엄 구독 운영) [16], 사용자가 직접 예상을 만드는 **코리아레이스 마패(MapAI)** [17], 그리고 개인화 AI **말고리즘** — 이건 **13일 전(2026-08-14) 마사회 공모전 수상작**이다 [18]. 학계에서도 KRA 데이터 LTR 논문이 **2편** 있고, 그중 하나는 **웹 서비스까지 만들어 2025년 11월에 게재**됐다 [12][13].

3. **9일 전, 방심위가 폴리마켓을 국내에서 차단했다** [14][15]. 논거는 "외피는 예측, 실질은 도박"이며 **"분산화 기술 특성으로 국내법 적용을 회피할 수 없다"**고 못박았다. SSAFY 명세서가 레퍼런스로 든 바로 그 서비스다. 심사·발표 자리에서 "경마 + 베팅 + 블록체인"의 첫인상이 이 뉴스와 겹친다.

**반면 8/21의 배제 사유였던 "사행성 정면"은, 조문을 읽어보니 정확한 진단이 아니었다.** 마사회법 제48조 1항 2호도, 게임산업법 사행성게임물 정의도 **"재물 또는 재산상의 이익"을 공통 요건**으로 한다 [6][8]. 비환금 토큰·폐쇄망이면 요건을 벗어날 여지가 있고, 무엇보다 **한국마사회 자신이 "경마 예상정보 제공 자체는 불법요소가 없다"고 공식 확인**했으며 [11], 마사회가 직접 AI 경마 공모전을 열어 상을 준다 [18].

> **경마는 "불법이라서" 탈락하는 게 아니라 "블록체인이 필요 없어서" 탈락한다.**

**단, 경마에는 애널리스트안이 못 가진 결정적 강점이 하나 있다 — 사이클 속도.** 주당 약 50경주가 열리고 결과가 당일 확정된다. 애널리스트안의 최대 약점은 "목표주가 투자기간 6~12개월 → 7주 안에 예측→확정→정산 사이클이 안 돈다"였고, 그래서 백테스트와 단기 이벤트라는 우회를 만들어야 했다. **두 주제의 강점은 정확히 상보적이다.** 권고안은 이 상보성을 쓰는 쪽이다 — §7 R2.

**가장 큰 미해소 항목:** 경주 종료 → API 반영 지연시간. 3라운드를 파도 공개 문서에 없다 [5]. **API 키 발급 후 경마 시행일 실측만이 유일한 경로다.**

## 1. 차원 A — 데이터 실사용성

### 1.1 API는 실존하고, 기대보다 좋다

한국마사회는 공공데이터포털에 경마 관련 오픈 API 수십 종을 제공한다 — 출마표·성적·구간기록·레이팅·혈통·훈련기록·기수/조교사 전적·확정배당률·매출까지 [2]. 기획서가 나열한 API ID들은 실존이 확인된다.

`경주별상세성적표`(15089492)는 실존하며 엔드포인트는 `https://apis.data.go.kr/B551015/racedetailresult/getracedetailresult`, 파라미터는 `meet`(1.서울/2.제주/3.부산경남), `rc_date`, `rc_no`, `pageNo`, `numOfRows`다 [1]. 제공 필드는 경주일자·경주번호·착순·출주번호·마번·마명·경마장·산지·성별·연령·**부담중량**·기수번호·수습기수감량·기수명·조교사·마주·도착차·**마체중·마체중증감**·**단승식배당율·연승식배당율**·경주기록·**레이팅**·장구현황·출주여부 [1].

기획서가 `[미확인]`으로 남긴 항목 중 **가장 중요한 것들이 긍정적으로 해소됐다**:

| 항목 | 확인 결과 | 출처 |
|---|---|---|
| **이용허락범위** | **"제한 없음"**, 비용 무료 | [1][5] |
| 활용승인 | 개발단계 **자동승인** / 운영단계 심의승인 | [1][3][4] |
| 트래픽 | **개발계정 3,000건/일**, 운영계정은 활용사례 등록 시 증액 | [3][4][5] |
| 유지보수 | 등록 2021-09-23, **수정 2026-08-16** (11일 전) | [1] |
| 포맷 | **JSON + XML** 동시 제공, REST | [4] |

**백필 산술 (실측으로 갱신 [27]):** `rc_month` 단위로 긁으면 27년치(2000~2026) 전량이 **972콜**이다. 개발계정 3,000콜/일 → **1계정으로 하루 안에 끝난다. 다계정 분산은 불필요.** 실제 규모는 **697,876행**(말-경주 단위)으로, 기획서의 "5년 ≈ 13만 행" 추정보다 5배 이상 크다.

### 1.2 AI학습용 전용 데이터셋이 신설되어 있다

`AI학습용_경주결과`(15143803)는 2025-06-05 등록, **2026-08-07 수정**된 신규 데이터셋이다 [4]. 파라미터는 `rccrs_cd`·`race_dt`이며 **경마장 코드가 1=서울, 2=제주, 3=부산경남, 4=영천** — 기획서가 `[추정]`으로 적었던 **2026년 영천 경마장 개장이 API 파라미터로 확인**됐다 [4]. 제공 필드는 마명·산지·마체중·레이팅, 기수·조교사, 경주 제원(거리·주로·경주번호), 결과(착순·기록·배당률), 마주 정보다 [4].

마사회가 이런 데이터셋을 새로 연 배경도 확인된다 — "정부의 AI 및 공공데이터 활용 활성화 정책에 맞춰 말산업 분야에서 민간 활용도가 높은 데이터를 발굴·개방" 중이며, 공모전 수상작에 "**AI 관련 경마 데이터 개방 활성화 방안을 수립**하겠다"고 밝혔다 [18].

### 1.3 날씨와 주로상태 — **이 절의 초판 서술은 실호출로 뒤집혔다** [27]

초판은 "KRA API에 날씨·주로상태가 없어 기상청 조인이 필요하다"고 적었다. **틀렸다.** 팀이 신청한 `경주기록 정보`(15058305 / `API4_3/raceResult_3`)의 실응답에 **`weather`와 `track`이 둘 다, 충전율 100%로 존재**한다 [27].

```
"weather": "맑음",  "track": "포화 (16%)",  "wgHr": "465(+9)",  "wgBudam": 54.5
```

초판이 근거로 삼은 것은 `경주별상세성적표`(15089492)와 `AI학습용_경주결과`(15143803)의 **공개 페이지 필드 목록**이었고, 그 두 API에 없다는 것은 지금도 사실이다 [1][4]. 오류는 **거기서 "KRA API 전체에 없다"로 일반화**한 데 있었다. 필드는 다른 API에 있었다.

- `weather` 분포(2026-05, 2,580행): 맑음 2,083 · 흐림 383 · 비 104 · 안개 10
- `track` 은 `"양호 (7%)"` 형식이라 **범주와 함수율 연속값을 동시에** 뽑을 수 있다: 건조 1,350 · 양호 582 · 다습 578 · 불량 70

→ **기상청 조인은 불필요하다.** 기획서 Q3 표의 "환경: 날씨, 주로 함수율/상태" 행은 옳았다.

### 1.4 실시간성 — 유일하게 해소되지 않은 항목

`경마시행당일_경주결과종합`(15119524)은 주로상태·등급·착순·마필·기수·조교사와 함께 **실제/예정 발주시각, 취소여부, 확정여부, 구간 통과순위**를 제공하고, **요청 파라미터에 `final_bit`(확정여부)가 있다** [5]. 확정 전/후를 구분해 조회하도록 설계됐다는 뜻이므로, 경주 직후 미확정 데이터에 접근할 가능성을 시사한다.

**그러나 갱신주기와 실제 반영 시점은 3개 데이터셋 페이지 어디에도 기재되어 있지 않다** [1][4][5]. 3라운드를 팠고, 공개 문서로는 확인이 불가능하다는 것이 결론이다.

**실호출로 부분 확인 [27]:** 전일(2026-08-26 수) 경주 데이터는 익일 완전히 조회된다(서울 103 · 제주 67 · 부경 103행). 즉 **지연 상한은 약 1일**. 그러나 "경주 종료 후 몇 분인가"는 여전히 미확인 — 검증일(8/27 목)에 경주가 없어 측정이 불가능했다. **`probe_latency.py`를 경마 시행일에 실행하면 닫힌다.** → §8 미해결 질문 1번.

## 2. 차원 B — 법률·사행성 (8/21 배제 사유의 재심)

### 2.1 조문 원문 — 공통 요건은 "재산상의 이익"

**한국마사회법 제48조(유사행위의 금지 등)** [6]:

| 항 | 금지 대상 | 내용 |
|---|---|---|
| 1항 1호 | 마사회가 아닌 자 | 경마를 시행하는 행위 |
| **1항 2호** | 마사회가 아닌 자 | 마사회 경주에 관하여 승마투표와 비슷한 행위를 하게 하여 **적중자에게 재물 또는 재산상의 이익을 지급하는 행위** |
| 2항 1호 | 누구든지 | 외국 말 경주에 전자적 방법으로 국내에서 승마투표 유사행위 → 적중자에게 재물/재산상 이익 지급 |
| 2항 2호 | 누구든지 | 영리 목적 마권 구매 대행·알선·양도 |
| **3항 1호** | **누구든지** | **배당률, 경주화면·음성, 컴퓨터 프로그램 등을 복제·개작·전송하는 행위** |
| 3항 2호 | 누구든지 | 정보통신망 이용 마권 시스템 설계·제작·유통·공중이용 제공 |
| 3항 3호 | 누구든지 | 위 행위들의 홍보 |

위반 시 **제50조 제1항: 7년 이하 징역 또는 7천만원 이하 벌금**(미수범 처벌, 징역·벌금 병과 가능) [7]. 단속 실무 보도에서도 동일한 형량이 확인되며, **사설마권 구매자는 5년 이하 징역/5천만원 이하 벌금, 홍보자는 3년 이하/3천만원 이하**가 적용된다 [21].

**게임산업진흥에 관한 법률 제2조 제1의2호** [8] — "사행성게임물"이라 함은 다음 각 목에 해당하는 게임물**로서, 그 결과에 따라 재산상 이익 또는 손실을 주는 것**을 말한다:

- 가. 베팅·배당을 내용으로 하는 게임물
- 나. 우연적 방법으로 결과가 결정되는 게임물
- **다. 「한국마사회법」에서 규율하는 경마와 이를 모사한 게임물**
- 라. 경륜·경정 모사 / 마. 카지노 모사 / 바. 대통령령으로 정하는 게임물

**구성요건이 결합형이라는 점이 핵심이다** — (i) 가~바 중 하나 **AND** (ii) 결과에 따른 재산상 이익/손실. **"경마 모사"만으로는 사행성게임물이 되지 않는다.**

### 2.2 예측·분석 제공은 적법하다 (실증 3건)

- **한국마사회 공식 입장(2025-10-26 보도): "리딩방의 경마 예상정보 제공 자체로는 불법요소가 없으며, 사설경마 등 마사회법 위반 행위가 있을 경우만 단속대상"** [11]
- 경마 예상 앱이 Apple App Store·Google Play에 정상 유통 중 [16][22]
- **마사회가 직접 AI 경마 공모전을 열어 상을 주고 데이터 개방을 확대한다** [18]

→ **8/21의 "사행성 정면" 판정은 과한 진단이었다.** AI 예측·분석 플랫폼은 명백히 적법 영역이다.

### 2.3 그러나 세 가지 실제 위험이 있다

**(1) 제48조 3항 1호 — 실시간 기획 직격.** "**배당률**, **경주화면·음성**, 컴퓨터 프로그램 등을 복제·개작·전송"을 **누구든지** 금지한다 [6]. 기획서의 "주말에는 실시간으로 맞추기"가 **경주 중계 화면을 서비스에 띄우는 것을 의미한다면 정면 위반**이다. 배당률도 같은 조문에 들어 있다 — 마사회가 공공데이터로 "이용허락범위 제한 없음" 개방한 분량을 약관대로 쓰는 것은 방어 가능하다고 보이나, **이에 대한 명시적 유권해석은 확인하지 못했다**(§8-4).

**(2) 베팅이 들어가는 순간 등급분류가 꼬인다.** 게임물관리위원회 공식 입장 — "**경주 대상에 대한 베팅 행위 및 배당을 받는지의 여부**, 게임산업법 제2조 1의2 다목의 경마 모사 해당 여부 등이 종합적으로 검토되어야 등급분류 가능 여부 및 연령등급이 결정된다" [9]. 게임위는 "베팅이 없다면 사행성 모사를 이유로 청소년이용불가를 받을 가능성은 낮다"고 했으나, 역으로 **유료 게임머니든 무료 게임아이템이든 베팅하는 게임은 청소년이용불가로 분류**된다 [9]. 그리고 게임산업법 제21조의 **비영리 게임물 등급분류 예외는 "청소년이용불가 등급에 해당하는 내용이 포함된 경우 제외"**된다 [10].

→ 폐쇄 교육 프로젝트로 두는 한 등급분류 의무 자체가 발생하지 않을 여지가 크지만, **팀이 명시한 도전 과제인 "빠른 론칭 → 유저 테스트 → 피드백"과 정면으로 충돌한다.**

**(3) 폴리마켓 차단 — 9일 전.** 2026-08-18 방심위가 접속차단을 의결했다 [14][15]. 논거는 형법상 도박·도박장소 개설 방조 정보 및 **국민체육진흥법상 유사행위** 해당이며, "승자독식 손익구조 + 우연성 의존"으로 실질적 불법 도박 환경을 제공한다는 것이다. 방심위는 **"한국어 서비스 제공 여부나 분산화 기술 특성으로 국내법 적용을 회피할 수 없다"**고 명시했다 [14]. 국민체육진흥법 제26조도 마사회법과 동일하게 **"적중자에게 재물이나 재산상의 이익을 제공"**을 요건으로 하며, 제2항은 **"유사행위를 위하여 해당 운동경기 관련 정보를 제공하는 행위"**까지 금지한다(제53조: 3년 이하 징역 또는 1,500만원 이하 벌금) [20].

### 2.4 설계별 법적 지위 판정

| 설계 | 법적 지위 | 근거 |
|---|---|---|
| AI 예측·분석 정보만 제공 | **적법** | 마사회 공식 입장 + 앱 유통 실증 + 마사회 공모전 [11][16][18] |
| 비환금 포인트 참여, 배당 없이 정확도 순위만 | 방어 가능 | "재산상 이익" 요건 미충족 [6][8] |
| 비환금 토큰 베팅 + 패리뮤추얼 배당 정산 | **회색지대** | 유통 시 최소 청소년이용불가, 비영리 등급분류 예외에서도 탈락 [9][10] |
| 토큰에 환금성·경품 부여 | **7년 이하 징역** | 제48조 1항 2호 정면 위반 [6][7] |
| 경주화면·음성 또는 배당률 재전송 | **정면 위반** | 제48조 3항 1호 [6] |

SSAFY 명세는 **Besu 프라이빗 체인 + 비환금 ERC-20 + 기수/지역/반 한정 참여**를 강제하므로(명세서 pp.6-8), 명세를 그대로 따르는 한 위 표의 3행(회색지대)에 머문다. **4·5행으로 넘어가지 않는 것이 절대 조건이다.**

## 3. 차원 C — 모델 성립성

### 3.1 접근법은 국내 데이터로 2회 독립 검증됐다

기획서가 지목한 KCI 논문은 실존한다 — **"Machine Learning-based Learning-to-Rank Approach for Horse Race Prediction and Web Service Development"**, 저자 Yubin So·Eunbi Woo·Hanjun Lee, 한국컴퓨터정보학회논문지 Vol.30 No.11, pp.311-318, **2025-11-28** [12]. KRA 제공 **2024.5~2025.4, 9,140 경주 기록**으로 LightGBM/XGBoost/CatBoost + **Listwise LambdaRank**를 비교하고 NDCG/MAP/MRR로 평가했다.

**기획서가 몰랐던 두 번째 논문도 있다** — "Horse race rank prediction using learning-to-rank approaches", 응용통계연구(The Korean Journal of Applied Statistics) [13]. 서울 경마 대상으로 point-wise vs pair-wise를 비교했고, RankNet·LambdaMART(XGBoost/LightGBM/CatBoost Ranker)를 사용해 **pair-wise가 point-wise보다 우수, CatBoost Ranker 최고 성능**을 보고했다.

→ **"경주 단위 상대비교 LTR"이라는 프레이밍은 방법론 리스크가 사실상 없다.** 기획서의 Q2·Q4 답변("말마다 모델을 만들지 않는다, 클러스터링도 아니다, 단일 모델이 경주 내에서 비교한다")은 옳다.

데이터량 추정도 교차 검증된다 — 공개 프로젝트 하나가 서울 단일 경마장 3년치로 **26,828행**을 확보했고 [23], 논문은 1년치로 9,140 경주를 썼다 [12]. 기획서의 "5년 ≈ 13만 (말-경주) 행" 추정과 정합한다.

### 3.2 기획서 정정 — 인용에서 빠진 반전

기획서는 "CatBoost NDCG 0.8895"만 인용했다. **논문의 실제 결론은 한 겹 더 있다: CatBoost가 랭킹 품질은 최고(NDCG 0.8895, MAP 0.4204)였으나, 실제 베팅 시나리오에서는 LightGBM과 XGBoost가 더 높은 예측 정확도를 보였다** [12].

**이것은 실무적으로 중요한 시사점이다 — 랭킹 지표 최적화 ≠ 베팅 성과 최적화.** 발표에서 "NDCG를 올렸다"가 아니라 "적중률/기대값을 올렸다"로 평가축을 잡아야 하며, 두 지표가 갈라진다는 사실 자체가 좋은 발표 소재다.

### 3.3 그러나 차별화 압박이 크다

논문이 쓴 피처는 **최근 경주 성적, 통산 평균 착순, 부담중량, 마령 — 4개 계열뿐**이다 [12]. 그것만으로 NDCG 0.8895를 냈고, 거기에 더해 **"순위 결과를 시각화하고 초보 사용자도 직관적으로 의사결정할 수 있는 웹 기반 예측 시스템"까지 개발했다** [12].

즉 **"AI로 경마 예측하는 웹서비스"는 9개월 전에 논문으로 나왔다.** 재현은 기여가 아니다. 차별화가 나올 자리는 좁게 남는다: 피처 엔지니어링 깊이(구간기록·혈통·기수-마 콤비·거리 적성), **확률 보정**(softmax + Platt/isotonic), **배당률 포함/제외 2모델 비교**, 기대값 기반 **백테스트 ROI**, **시간순 분할**의 엄격한 준수. 기획서가 이 항목들을 이미 짚어둔 것은 정확하다.

## 4. 차원 D — 시장·경쟁·차별화

### 4.1 직접 경쟁자 3곳이 전부 실서비스다

| 서비스 | 무엇 | 팀 기획과 겹치는 축 |
|---|---|---|
| **경마선생 — AI 경마예상** [16] | 공공데이터 기반 AI가 경주기록·실시간 데이터 분석해 결과 예측. 전 경마장 지원. **프리미엄 구독 운영** | ① AI 예측 |
| **코리아레이스 마패(MapAI)** [17] | AI 예상 참고 + **사용자가 직접 예상을 만드는** 툴 | ② 나만의 커스텀 모델 |
| **말고리즘 (Horse IT 개발)** [18] | 공공데이터 AI 앱. 이용자 메모·복기노트를 AI가 분석해 개인화. **2026-08-14 마사회 공모전 수상** | ③ 개인화 |

**팀 기획의 AI 3축이 각각 이미 상용 서비스로 존재한다.** 특히 말고리즘 수상은 **13일 전** 사건이다. 패키지명 `kr.co.publicdata.horse`가 말해주듯 경마선생은 정확히 같은 공공데이터 소스를 쓴다 [16].

### 4.2 마사회 공모전 — 기회이면서 동시에 닫힌 문

**제11회 대한마사회 창의·혁신 아이디어 공모전 + AI 활용 창의혁신공모전**은 298개 아이디어가 접수돼 금상 3·은상 3·동상 12 등 18개를 선정했고 **2026-08-14 결과가 발표됐다** [18]. 마사회는 "향후 AI 관련 경마 데이터 개방 활성화 방안을 수립하고, 우수 아이디어에 대한 사업화 지원과 데이터 구축 지원을 추진하겠다"고 밝혔다 [18].

**수상 80%가 목표인 팀에게는 매력적인 트랙이지만, 이번 회차는 이미 끝났다.** 공공데이터포털의 2026년 공공데이터 활용 경진대회 목록에도 마사회 주관 대회는 확인되지 않는다 [24]. **7주 프로젝트 기간 내에 출품 가능한 마사회 공모전은 없다고 봐야 한다.**

### 4.3 시장은 축소 중이고, 도달 가능한 모수는 작다

- 합법경마 매출액 2008년 7.4조원 → 2024년 6.5조원 [26 — 신뢰도 낮음, §8-6]
- 온라인 마권은 2024-06 정식발매, **발매 총량이 경마 총매출의 10%로 제한**됨(사행성 확산 방지), 2025년도 동일 [19][25]
- 온라인 플랫폼 '더비온' 누적 등록자 **91,943명**(2025-02말), 이용자의 **약 90%가 1만원 이하 소액** [19]

**다만 이 프로젝트에서 "시장"의 의미는 제한적이다.** SSAFY 명세는 참여 대상을 **기수·지역·반 조건으로 한정**하고 비환금 토큰을 쓰도록 강제한다(명세서 p.6). 상업적 TAM은 애초에 접근 대상이 아니며, 실질적 평가축은 **(a) 심사에서의 차별성**과 **(b) 면접에서의 서사**다. 그 두 축에서 §4.1의 경쟁 지형이 그대로 리스크가 된다.

## 5. 교차 차원 인사이트

**(1) 데이터가 좋을수록 블록체인 당위성이 약해진다 — 이것이 이 주제의 구조적 모순이다.**
차원 A는 "마사회가 결과를 공신력 있게, 무료로, 제한 없이, 빠르게 확정 발표한다"는 것을 확인했다. 바로 그 사실이 차원 B·D에서 독이 된다. 팀이 정의한 블록체인 3조건 중 **조건 2 "결과 검증자가 거짓말하면 예치금을 잃음"이 성립할 수 없다** — 거짓말할 검증자가 없기 때문이다. 오라클 스테이킹·슬래싱·이의제기 기간은 경마에서 순수한 장식이 된다. 심사위원이 "왜 블록체인이어야 하나"를 물었을 때 답이 조건 1·3(에스크로 + 자동정산)으로 축소되는데, **그 둘은 8/21 트리아지에서 "예측 플랫폼 아님(에스크로·이력관리)" 사유로 7건을 배제할 때 쓴 바로 그 기준이다.**

**(2) 법률 리스크의 실체는 "사행성"이 아니라 "제48조 3항 1호"였다.**
8/21 트리아지는 경마를 "사행성 정면"으로 배제했다. 조문을 읽으면 그 진단은 과했다 — 재산상 이익 요건이 공통 게이트이고, 마사회 스스로 예상정보 제공을 적법으로 확인했다 [11]. 그런데 아무도 보지 못한 조항이 하나 있었다: **배당률·경주화면·음성의 복제·전송 금지** [6]. 이것이 기획의 "주말 실시간" 축을 직접 겨눈다. **틀린 이유로 배제했다가, 맞는 이유를 놓친 셈이다.**

**(3) 경마의 진짜 강점은 AI가 아니라 사이클 속도인데, 기획서는 그걸 강점으로 세우지 않았다.**
차원 C·D는 AI 차별화 공간이 좁다는 것을 보여준다. 그러나 차원 A는 **주당 약 50경주, 당일 결과 확정**이라는 사실을 확인했다. 8/21 확정안(애널리스트 리포트 검증)의 문서화된 최대 약점이 정확히 이것이었다 — "목표주가 투자기간 6~12개월 → 7주 안에 사이클이 안 돈다". **두 주제의 강점과 약점이 정확히 반대로 맞물린다.** 이것이 §7 R2의 근거다.

**(4) 폴리마켓 차단은 위협이자 서사다.**
명세서가 레퍼런스로 든 서비스가 9일 전 국내에서 차단됐다 [14][15]. "블록체인 예측 = 도박"이라는 프레임이 지금 가장 강한 시점이라는 뜻이다. 동시에 **"폴리마켓이 차단된 이유를 조문 단위로 분석하고 그것을 통과하도록 설계했다"**는 것은 어떤 주제를 고르든 발표에서 강력한 한 장이 된다.

## 6. 반대 근거 (경마를 지지하는 가장 강한 논거)

공정하게, 경마 채택을 지지하는 근거도 실재한다:

- **데이터 품질·비용·라이선스가 이 프로젝트에서 만날 수 있는 최상급이다.** 무료, 이용허락범위 제한 없음, 자동승인, JSON 제공, AI 학습용 전용 데이터셋 신설, 3주 내 갱신 [1][4][5]. 대조적으로 애널리스트안의 데이터 소스는 **네이버 금융 크롤링 — 공식 API가 아니며 저작권 가드레일이 필요**하다(brainstorm-intent가 스스로 "시작 전 확정 필요" 1번으로 적어둔 항목).
- **결과 확정이 100% 자동·객관적이다.** 오라클 구현 난도가 가장 낮고, 7주 안에 정산 사이클을 수백 번 돌릴 수 있다.
- **마사회가 이 영역을 장려한다** — 공모전 개최, AI 데이터 개방 확대 방침 [18]. 합법성 리스크의 실질은 낮다.
- **AI 정량 성과를 낼 수 있다.** 배당률 내재확률이라는 명확한 시장 베이스라인이 존재해 "시장 대비 +Xp"라는 검증 가능한 지표가 나온다 — 이는 애널리스트안에는 없는 강점이다.

**이 논거들의 공통 한계:** 전부 "좋은 데이터 프로젝트"의 근거이지 **"블록체인이 필요한 프로젝트"의 근거가 아니다.** 그리고 이것은 블록체인 프로젝트다.

## 7. 권고

**R1 — 경마를 프로젝트의 본체 주제로 삼지 말 것. (신뢰도: 높음)**
근거는 §5(1) — 팀 자신의 블록체인 3조건 중 조건 2가 구조적으로 성립하지 않는다. 보조 근거는 §4.1의 경쟁 포화와 §2.3(3)의 규제 인상 리스크. **다만 8/21 트리아지의 배제 사유는 "사행성 정면"이 아니라 "블록체인 당위성 결여"로 정정할 것** — 사유가 틀리면 유사 주제를 판단할 때 같은 실수가 반복된다.
→ 소비처: 브레인스토밍 트리아지 사유 정정, 제품 브리프의 "배제된 대안" 절.

**R2 — 8/21 확정안(애널리스트 리포트 검증)을 유지하되, 경마를 "빠른 사이클 이벤트 카테고리"로 편입할 것. (신뢰도: 중간 — §5(3)의 상보성 관찰에 근거)**
SSAFY 명세는 `PredictionEventFactory`가 **이벤트별 `PredictionEvent`를 배포하는 구조**이며 이벤트 생성 시 **카테고리를 입력받는다**(명세서 pp.6-7). 즉 한 플랫폼에 복수 이벤트 카테고리를 담는 것이 명세 그 자체다. 배치는:

- **애널리스트 축** = 블록체인 당위성(틀린 전망의 은폐 방지) + 문제의식 + RAG 당위성
- **경마 축** = 7주 안에 수백 회 도는 정산 사이클 + AI 정량 성과(시장 배당률 대비) + 무료·무제한 데이터

경마 축은 **베팅이 아니라 "AI 예측을 온체인에 박제하고 채점한다"**로 프레이밍한다. 이러면 조건 2가 필요 없는 축이라는 사실이 문제가 되지 않는다 — 조건 2는 애널리스트 축이 담당한다.
→ 소비처: 제품 브리프(범위), PRD(이벤트 카테고리 정의), 아키텍처(Factory 카테고리 모델).

**R3 — 어떤 안을 고르든 아래 3개를 설계 불변식으로 못 박을 것. (신뢰도: 높음 — 조문 원문 근거)**

1. **토큰에 어떠한 환금성·경품 교환도 부여하지 않는다** — 위반 시 마사회법 제48조 1항 2호, 7년 이하 징역 [6][7]
2. **경주 중계 화면·음성을 서비스에 전송하지 않는다. 배당률은 공공데이터 API로 취득한 확정치만 사용한다** — 제48조 3항 1호 [6]
3. **참여 대상을 SSAFY 기수/지역/반으로 한정한 폐쇄망을 유지한다** — 명세 요구이자 게임물 등급분류 의무 회피의 근거 [9][10]

→ 소비처: 아키텍처 스파인의 불변식(invariants), PRD의 비기능 요구.

**R4 — "빠른 론칭 → 유저 테스트" 도전 과제를 법률 제약과 함께 재정의할 것. (신뢰도: 중간)**
브레인스토밍이 정한 도전 과제는 외부 유저 테스트를 전제하지만, §2.3(2)에 따르면 **베팅 메커닉이 있는 채로 외부 공개하면 등급분류 이슈가 살아난다.** 유저 테스트 모수를 SSAFY 내부로 한정하거나, 외부 공개 버전은 베팅을 제거한 조회 전용으로 분리하는 두 갈래 중 하나를 W1에 확정할 것.
→ 소비처: 제품 브리프(사용자 정의), 스프린트 계획(W1 게이트).

**R5 — 경마를 어떤 형태로든 쓴다면, W1에 API 키로 실측할 3개 항목을 게이트로 둘 것. (신뢰도: 높음)**
§8의 미해결 질문 1~3. 특히 **반영 지연 실측 전에는 "주말 실시간" 기능을 커밋하지 말 것.**
→ 소비처: 스프린트 계획 W1 준비도 게이트.

## 8.5 실호출 검증 (2026-08-27 · 인증키 발급 후) [27]

팀이 data.go.kr 개발계정 인증키를 발급하고 7종을 승인받아, **전부 실호출로 검증했다(7/7 `resultCode=00`).** 전체 결과는 같은 폴더의 **`data-inventory.md`**에 있다. 이 리서치의 결론에 영향을 주는 것만 옮긴다.

### 뒤집힌 것 1건 — 날씨·주로상태

§1.3 참조. 초판의 "KRA API에 없다"는 **오판**이었다. `API4_3/raceResult_3`에 `weather`·`track` 모두 **충전율 100%**로 존재한다. 기상청 조인 불필요.

### 확정된 것

| 항목 | 실측값 |
|---|---|
| 승인 7종 동작 | **7/7 정상** |
| 학습 원장 | `API4_3/raceResult_3` — **필드 93개** |
| 과거 커버리지 | **2000년~현재, 697,876행** (1998년 이전 0) |
| 백필 비용 | `rc_month` 단위 **972콜** = 1계정 하루 |
| 결측 | weather·track·wgHr·wgBudam·ord·ilsu = **100%** · 배당률 98% · **`rating` 76%**(유일한 실질 결측) |
| 반영 지연 | **상한 약 1일** 확인. 분 단위는 여전히 미확인 |

선행 KCI 논문이 쓴 데이터는 **9,140경주(1년치)**다 [12]. 팀은 **27년치를 쓸 수 있다** — §3.3에서 지적한 차별화 부족에 대한 첫 번째 실질적 지렛대다.

### 새로 드러난 위험 2건

**(1) 출마표가 없다 — 지금 구성으로는 "경기 전 예측"이 불가능하다.**
승인된 7종은 **전부 경주 *결과* 계열**이다. 발주 전 예측의 입력이 되는 **출마표(`AI학습용_경주계획`, 15143802 / `API154/racePlan`)가 신청 목록에 없다.** 이것 없이는 예측 서비스 자체가 성립하지 않는다. 자동승인이므로 즉시 추가 신청할 것. 함께 검토할 것: `경마시행당일_경주결과종합`(15119524 / `Race_Result_total`) — `final_bit`가 지연 실측과 라이브 정산에 필요하다.

**(2) 통산전적 API 3종은 그대로 쓰면 누수를 만든다.**
`API15_2/raceHorseResult_2`(경주마 성적), `API77/raceHorseRating`(레이팅), `trtresult/gettrtresult`(조교사)는 모두 **오늘 기준 누적 스냅샷**이다. 과거 경주 행에 붙이면 모델이 미래를 안 채로 예측하게 된다. 통산·최근 성적류는 **`API4_3` 원장에서 경주일 이전 데이터만으로 직접 rolling 집계**해야 한다. (`API4_3`의 `rating` 필드는 경주 시점 값이라 누수가 없다.)

### 기획서 정정 1건 — 평일에도 경주가 있다

기획서는 "평일(월~목)에는 경주가 없다 → '평일 = 과거 경기 리플레이' 기획이 데이터 현실과 정확히 부합한다"고 적었다. **부분적으로 틀렸다.** 기본 편성이 금·토·일인 것은 맞지만, 2026년 들어 월·화·수 예외 편성이 발생한다 [27]:

| 월 | 경주일수 | 요일 분포 |
|---|---|---|
| 2025-02 · 06 · 11 | 10~14 | 금·토·일만 |
| 2026-03 | 14 | **월1** + 금4 토4 일5 |
| 2026-07 | 14 | **월1 화1** + 금4 토4 일4 |
| **2026-08** | 16 | **월2 화1 수1** + 금4 토4 일4 |

목요일만 0이다. **"평일=리플레이"를 요일로 하드코딩하면 실경기와 충돌한다** — 경주 유무를 API로 조회해 분기할 것.
