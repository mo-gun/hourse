팀원 6명이 같은 데이터로 각자 다른 가중치 모델을 만들고 같은 기준으로 비교하기 위한 것.

- 분할 규약 요약(웹): https://claude.ai/code/artifact/df50d710-1b24-469e-8af2-d8c3ff04695c
- 컬럼 정의 단일 원천: `schema_v2.py`

## 2. 읽기

import pandas as pd

## 3. 지켜야 할 규칙 넷

**① `game`은 학습·검증·평가 어디에도 쓰지 않는다.**
사용자가 플레이할 경주다. 모델이 본 적 있으면 비정상적으로 잘 맞히고, "내 모델 vs 기본 모델 vs 시장" 비교가 통째로 무의미해진다.

**② `game_holdout.json`을 재생성하지 않는다.**
시드 `20260901`로 뽑은 408개 개최일. 이 파일이 바뀌면 예약이 무의미해진다.
2025~2026년도 학습에 넣어야 해서(주말 실시간 예측) 게임풀을 뒤쪽 시간 블록이 아니라 **2015~2024에 흩어서** 예약했다. 개최일 단위로 통째로 뺐다 — 경주 단위로 흩뿌리면 같은 날 앞뒤 경주가 학습에 남는다.

**③ `test`는 최종 1회만 연다.**
튜닝은 `valid`로. 802경주에서 top-1 적중률의 표준오차가 **1.7%p**이니 그보다 작은 차이는 우열로 읽지 않는다.

**④ 정렬을 바꾸지 않는다.**
parquet은 `race_id`로 묶여 있다. LightGBM의 `group`은 "연속된 N행이 한 경주"라고 가정하므로 셔플하면 **에러 없이 조용히 틀린 모델**이 나온다.

```python
g = tr.groupby("race_id", sort=False).size().to_numpy()   # 이 순서 그대로
```

## 4. 피처 82개

접두사가 곧 담당 그룹이다.

| 그룹 | 담당 | 피처 | 충전 |
|---|---|---:|---:|
| `X_` | 공통 — 전원 포함 | 10 | 95% |
| `F1_` | 최근 성적 · 조교 | 12 | 96% |
| `F2_` | 부모 성적 (육종가) | 11 | 40% |
| `F3_` | 기수 실력 | 6 | 93% |
| `F4_` | 거리 · 날씨 | 7 | 93% |
| `F5_` | 주행 스타일 | 6 | 94% |
| `F6_` | 인기도 | 4 | 100% |

여기에 **경주 내 정규화 26개**(주요 연속형 13개 × `_z`/`_rk`)를 더해 총 82개. 경마는 경주 안의 상대비교 문제라 절대값만으로는 부족하다 — `F3_jk_win_rate_365 = 0.15`가 좋은지는 같은 경주 다른 기수들에 달렸다.

**타깃**: `y_win`(1착) `y_plc`(3착 이내) `y_rel`(랭킹 라벨) `y_ord`(착순) `y_speed_fig`(스피드지수)

## 5. 먼저 알아야 할 것 — 기준선과 한계

실측한 숫자다. 모르고 시작하면 며칠 헤맨다.

| | top-1 | top-3 |
|---|---:|---:|
| **시장 (인기 1위마)** | **34.2%** | 65.7% |
| 인기도 포함 모델 (82피처) | **36.8%** | 68.8% |
| 인기도만 (4피처) | 35.9% | 68.2% |
| **인기도 제외 (78피처)** | **30.2%** | 64.0% |

**펀더멘털 피처만으로는 아직 시장을 못 이긴다.** 단일 피처로 순위를 매겨보면 이유가 보인다.

```
F1_ord_avg3        25.5%      F6_mkt_prob   36.1%
F1_ordpct_avg5     24.5%
F3_jk_win_rate_365 19.1%
F2_ebv_prize       18.8%
```

**배당률 하나가 펀더멘털 52개를 합친 것보다 강하다.** 시장 배당에는 우리에게 없는 정보가 들어있다 — 조교 내용에 대한 전문가 판단, 마방 상태, 부상, 당일 패독 컨디션.

이건 데이터 결함이 아니다. Tondapu(2024)가 100만 건으로 경마 베팅시장이 전통 금융시장보다 효율적임을 보였다. Benter가 5년 실전 수익을 낸 게 뉴스가 된 이유이기도 하다.

**시도해도 소용없던 것** (인기도 제외 조건, 전부 실측으로 기각):

| 수정 | top-1 |
|---|---:|
| 라벨을 등급형으로 | 30.3% |
| 범주형 native 처리 | 29.2% |
| 둘 다 | 28.1% |
| 경주 내 상수 피처 제거 | 28.9% |
| 이진분류로 전환 | 30.8% |

반면 **경주 내 정규화는 효과가 있었다** — 인기도 포함 모델이 35.7% → 36.8%.
기여도 1위가 `F1_ordpct_avg5_z`(31.5%)로, 절대값이 아니라 경주 내 상대값이 실제로 일을 한다.
다만 인기도 제외 조건에서는 개선이 없었다(30.9% → 30.2%).

**과대적합이 있다.** 라운드를 늘리면 train만 오른다 — 200it에서 train 42.7 / test 30.7, 2000it에서 train 72.8 / test 29.6. `valid` 최고점이 200 rounds 근처이니 정규화를 세게 걸고 시작할 것.

**권하는 방향**: 시장을 이기려 하지 말고 **결합**한다. Benter 2단계 — 펀더멘털 모델을 만든 뒤 공개 배당과 합친다. 게임에서는 배당이 확정돼 있어 `F6_*`를 쓸 수 있다.

## 6. 시점 태그 — 실수 방지

`tier=G`가 붙은 `F6_*` 4개는 **리플레이 전용**이다. 과거 경주는 배당이 확정돼 있어 쓸 수 있지만, **주말 실시간 경기는 발주 4분 전에도 배당이 0행**이다(실측). 실시간 모델은 반드시 이렇게 만든다.

```python
cols = features(exclude_tier=("G",))
```

즉 **모델이 두 개 나온다** — 게임용(82개)과 주말 실시간용(78개).

## 7. 누수 방지 — 어떻게 만들었나

`validate_v2.py`가 매 빌드마다 검사하고, 현재 전 항목 통과·경고 0건이다.

- **as-of 단일 패스**: 행마다 `emit`(현재까지 누적) → `update`(이 경주 반영) 순서. 구조적으로 미래를 볼 수 없다. 원장에서 독립 재계산해 대조한 결과 **100.000% 일치**(n=445,351)
- **기준기록(par)은 train에서만** 산출. valid/test로 만들면 그 자체가 누수
- **육종가는 경주일 직전 스냅샷만**. 육종가는 그 말 자신의 성적을 포함해 계산되므로 최신 스냅샷을 과거 경주에 붙이면 미래를 보게 된다. 반기 스냅샷 20개(2016-07~2026-06) 중 직전 것만 붙였고 위반 0건
- **게임풀 격리**: `game` 경주가 train/valid/test에 0건

**쓰면 안 되는 원본 필드**가 있다. API의 통산성적(`rcCntT` `winRateT` `rcCnt` `avgWinDist` 등)은 **조회 시점 스냅샷**이라 과거 경주에 붙이면 미래가 샌다. 목록은 `schema_v2.FORBIDDEN`.

`ilsu`도 여기 들어있다 — 원장의 `ilsu`는 휴양일수가 아니라 **그 해 n번째 개최일**이다(2015 서울 실측: 개최일 순번과 상관 1.0000). 진짜 휴양일수는 `F1_layoff_days`.

## 9. 재생성

`data/raw/`의 원본(원장 199MB, 조교 146MB, 장제 68MB, 육종가 24MB)은 용량 때문에 커밋하지 않았다. 처음부터 만들려면:

```bash
python tools/backfill_ledger.py          # 원장 612콜 · 10분
python tools/backfill_aux.py train       # 조교
python tools/backfill_aux.py shoe        # 장제
python tools/backfill_aux.py pedigree    # 혈통
python tools/parse_ebv.py                # 육종가 xlsx 20개 파싱
python build_v2.py all                   # model + game + sim
python validate_v2.py
```

`.env`에 `KRA_API_KEY_ENCODED`가 필요하다(data.go.kr 개발계정, 무료·자동승인). 같은 원장과 같은 `game_holdout.json`이면 **결정론적으로 동일한 결과**가 나온다.
