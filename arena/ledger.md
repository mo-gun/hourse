# arena 실험 장부 — 기법 계열 비교 (건모)

한 실험 = 한 줄. 같은 자(팀 하네스 `pipeline/data/model/common.py` → `C.report()` / `C.evaluate()`)로
잰 것만 적는다. 비교는 valid. **test 는 열지 않는다.**

## 고정한 것 — 이걸 바꾸면 레포의 다른 표와 비교가 무효다

- **피처**: `common.feature_cols()` 가 주는 **77 / 73** 그대로. 늘리거나 줄이지 않는다.
  (같은 날 별건으로 마체중 `X_wgHr` 등록 작업이 있었지만 그건 79/75 가 되므로 **여기 쓰지 않는다.**
   arena 는 레포 정본 파케이 `pipeline/data` 를 그대로 쓴다)
- **데이터**: 팀 파케이. `usable()` 적용 후 train 381,966두 36,249경주 / valid 13,252두 1,254경주
- **전처리**: `common.load()` 그대로 = `schema_v2.clean()` + `usable()`
  ⚠ 정원님 장부는 `clean()` **미적용** 시절 값이라 기준선이 다르다(73: 34.0 vs 33.5).
    arena 의 기준선은 이 하네스에서 직접 재현한 값을 쓴다
- **정렬 유지** · **game 미사용**(하네스가 안 내준다) · **시드 3개 이상**
- 장치: RTX 4050 Laptop 6GB · 22코어. 이 표의 계열은 전부 **CPU**(GBDT·배깅)
- 콘솔: `PYTHONUTF8=1`

## 왜 이 계열들인가 — 레포가 안 덮은 곳만

| 축 | 근거 | 계열 |
|---|---|---|
| GBDT 다른 구현·목적함수 | "표 데이터는 GBDT" 가 정설인데 레포는 LightGBM lambdarank **한 설정**만 재봤다 | `lgb_xendcg` `lgb_binary` `xgb_*` `cat_*` `hist_gb` |
| **PL 우도를 트리로** | 레포의 Plackett-Luce 손실은 전부 **신경망**(S1~S5·AxisRanker)에만 얹혀 있었다 | `cat_querysoftmax` |
| 범주형 native | 팀 README 의 "범주형 native 악화(29.2)"는 LightGBM 얘기. CatBoost 는 기제가 다름 | `cat_*` |
| 배깅 | Lessmann 외(2010)가 RF > 조건부로짓 보고. `schema_v2.LIT` 에 `LS` 로 등재됐는데 미실행 | `rf` `extra_trees` |
| 결합식 | 레포가 세 번 같은 결론에 도달 — "결합식이 전부다". 최고 기록도 앙상블(35.3) | `arena.run_combine` |

### 진단 — 왜 계열을 늘려도 안 되나

경주 내 z-score 기준 계열 간 예측 상관 (14×14):

```
비대각 상관: 중앙값 0.942 · 최소 0.717 · 최대 0.992
```

계열끼리 사실상 같은 모델이다 — 같은 경주에서 같이 틀리니 앙상블로 얻을 게 적다.

**★ 예상과 달랐던 지점** — 가장 탈상관된 칸은 **모델 계열을 바꾼 것**(mlp_pl, 트리 대비
0.87~0.95 · lgb_lambdarank 와 0.95)이 **아니라 타깃을 바꾼 것**(lgb_speedfig 0.72~0.85)이었다.
lgb_speedfig 는 단독 성적이 최하위(29.43, 유의하게 나쁨)인데 **가장 다르게 틀린다** —
약하지만 다양한, 전형적인 앙상블 재료다. 구조를 바꾸는 것보다 **무엇을 맞히게 할지를
바꾸는 쪽**이 다양성의 지렛대다. 다음 재료는 그쪽에서 찾을 것.

## 판정

1. **계열을 바꾸는 것으로는 73피처 top-1 의 선을 넘지 못한다.** 14계열 29.43~34.69,
   유의한 차이는 딱 하나이고 그건 **나쁜 쪽**(lgb_speedfig −4.07%p)이다.
   `docs/02-모델.md` 의 "모델 자체로는 차별화 못 한다"가 실측으로 확인됐다.
2. **기존 선택(LightGBM lambdarank)이 근거 있다.** 트리 계열 중 확률 품질 1위(1.9113).
3. **PL 목적함수는 신경망에서 작동하고 트리에서는 아니다.** `cat_querysoftmax`(조건부로짓
   우도를 트리로) 32.30 으로 하위권. 레포가 PL 을 신경망에만 얹은 게 우연이 아니다.
4. **Lessmann(2010)의 "RF > 조건부로짓"은 이 데이터에서 재현되지 않았다** (32.14, 최하위권).
5. **단독 최고는 MLP+PL(34.53 / logloss* 1.9078)** 이고, epoch 을 valid 로 고르지 않았으므로
   낙관 보정이 필요 없다. 레포 S1~S4 는 valid 로 epoch 을 골랐으니 조건이 다르다.
6. **남은 지렛대는 결합과 타깃 다양성**이고, 둘 다 이미 경계선(p≈0.05)에서 멈춘다.

## 안 한 것 — 조용히 빠뜨리지 않으려고 적는다

- **77 갈래 계열 비교** — 77피처는 레포 전 모델이 38.9~39.9 로 시장 39.3 과 통계적 동률,
  이미 천장이다. 계열별로 다시 훑을 값이 없어 **Benter 2단계만** 쟀다.
- **계열별 하이퍼파라미터 정밀 튜닝** — 계열마다 기준선과 대응되는 **상식적 한 점**만 썼다.
  정원님 장부에 "하이퍼파라미터 탐색: 기본 설정이 최적" 이 이미 있고, 1차 목적이
  "계열을 바꿔서 선을 넘을 여지가 있나" 였다. 선 근처에 온 계열이 없으므로 튜닝으로
  2%p 를 메울 가능성은 낮다고 본다 — 다만 **재보지는 않았다.**
- **test** — 열지 않았다.

더해진다. 제품 관점에서도 주성분은 이름을 붙일 수 없어 **6축 슬라이더가 될 수 없다.**
→ **"지금 있는 73개를 섞기" 는 닫힌 방향이다.**

## ★ 결합 확정 (2026-09-10) — basemodel/ledger.md 열린 항목 #1 을 닫는다

Benter 2단계를 기저 6종에 각각 적합했다 (valid 2-fold 교차적합, `eta = a·log(시장확률) + b·s_z`):

| 기저 | fold1 b | fold2 b | 시장 대비 top-1 |
|---|---:|---:|---|
| **mlp_pl (신경망)** | **+0.295** | **+0.156** | −0.88 [−1.87, +0.12] p=0.126 → **동률** |
| lgb_lambdarank | +0.282 | +0.030 | −1.20 [−2.15, −0.24] p=0.017 ★열세 |
| lgb_binary | +0.145 | +0.017 | −0.96 [−1.87, −0.08] p=0.090 |
| hist_gb_norm | +0.274 | −0.042 | −0.80 [−1.71, +0.12] |
| hist_gb | +0.270 | −0.059 | −0.80 [−1.75, +0.16] |
| 앙상블 16개 | +0.261 | −0.022 | −1.04 [−1.91, −0.16] p=0.041 ★열세 |

시장 계수 a 는 전 기저에서 0.86~1.10 으로 안정적이다. **펀더멘털 계수 b 는 신경망 기저에서만
두 fold 모두 뚜렷한 양수로 살아남고, 트리 기저는 전부 0 으로 무너지거나 부호가 뒤집힌다.**

**결정 — 결합식은 시장을 별도 항으로 분리하고 계수를 명시한다:**

```
점수 = m · s_시장  +  Σ w_k · s_k        (m 은 프리셋 상수, w 는 슬라이더 6축)
```

근거 넷:
1. **배당을 원피처로 던지면 안 된다.** 77피처 LGB 의 gain 87.8% 가 F6 로 가고 펀더멘털이
   12% 로 희석된다(`arena.importance`). 결합비를 모델이 알아서 정하게 두면 언제나 시장을 베낀다.
2. **F6 를 6축 중 하나로 두는 것도 안 된다.** 정원 타워 35.33 vs 시장을 빼낸 배당형 37.88,
   **+2.55 [+0.48, +4.47] p=0.014**. 1/6 고정 희석이 −2.55%p 의 값이다.
3. **결합 계수는 held-out 에서 적합한다.** train 에서 적합하면 b 가 과하게 커진다 —
   basemodel 역배형 m 에서 이미 겪었고(train m=−0.50 이 전이 안 됨), 여기서도 fold2 에서
   트리 기저의 b 가 무너지는 것으로 재확인됐다.
4. **펀더멘털 기저는 신경망이어야 한다.** 트리 기저는 결합 후 기여가 0 이다. 정원님 S3 가
   logloss 에서 10/10 이겼던 것과 **독립적으로 같은 결론**이다 — 시장에 없는 정보를 실제로
   갖고 있는 건 신경망 쪽이고, 트리는 시장이 이미 아는 것만 본다.

정원님 §6-3 의 "베이스 항" 제안과 배타적이지 않다 — 베이스 항 = `Σ w_k s_k` 를 학습된
고정 가중치로 두는 것이고, 위 식은 그 위에 시장 항을 명시적으로 얹은 형태다. **둘 다다.**

## ★ H1 — 착차(마신차) 검정 (2026-09-10)

**가설을 먼저 적고 시작했다** (스캔이 아니라 검정):
> 착순 백분위는 마신차를 버린다. 머리 차 2착과 10마신 차 2착이 지금 같은 값이다.
> 착차를 수치화해 과거 성적에 붙이면 같은 착순 안에서 실력이 구분된다.
> → 모델 gain 의 30.3% 를 차지하는 `F1_ordpct_avg5_z` 의 정보량을 늘리는 것.

새 데이터 수집 **0건**. 원장 89컬럼 중 피처로 한 번도 안 쓰인 `diffUnit`(충전 90.5%)을 썼다.

### 구성 과정에서 실측으로 바로잡은 것 두 가지

1. **착차는 우승마 누적이 아니라 앞말과의 간격이다.** 누적으로 가정하면 조용히 오염된다.
   근거 — 부경 6R: 2착 `6`(우승마 대비 +1.0초) / 3착 `1¾`(+1.3초, 앞말과 0.3초)
   / 4착 `목`(+1.4초). 초당 5~6마신으로 일관. → 경주 내 착순 정렬 후 **cumsum** 해야 한다.
   교차검증: 누적마신 vs 기록차 상관 **r=0.9932**, 중앙값 5.67마신/초 (n=397,439).
2. **큰 정수는 코드값이 섞여 있다** (배당 9999.9 와 같은 함정). `500`(34행)의 실제
   기록차는 우승마 대비 32.6초 ≈ **185마신** 이라 500 이라는 숫자 자체가 코드다.
   분포도 99까지 연속이고 그 위는 101/105/120/150/200/300/500 으로 띄엄띄엄하다.
   → 값을 만들어 넣지 않고 **99.5분위(41.75마신)에서 윈저화**. 잘린 행 0.497%.

그리고 **키가 한 번 어긋났다** — `race_id` 를 만들 때 `meet` 를 원문 문자열("부산경남")로
써서 파케이(숫자 코드 `3`)와 교집합이 **0** 이었다. 그대로 갔으면 전부 결측인 채로
"효과 없음" 이 나왔을 것이다. `MEET_CODE` 매핑 후 train/valid 조인 **100.00%**.

## ★ H2 — 경쟁 강도 검정 (2026-09-10)

**가설:** 같은 착순이라도 상대 수준이 다르다. `5,000점초과` 의 2착과 `350점이하` 의
2착이 지금 같은 값이다. Benter 3번 범주의 나머지 절반(H1 은 "마신차" 축).

### prizeCond 를 쓰지 않았다 — 전제를 먼저 확인한 결과

피처를 만들기 **전에** `prizeCond` 를 열어봤더니 **246개 이질 표기**였다:
`R0~0`·`R1~35`(레이팅 구간) / `350점이하`(점수) / `1,200만원이하`(금액) /
`(1년)1000점이하`(기간 한정). 최소 4개 체계가 섞여 있어 하나의 수치로 파싱하면
잡음과 행정적 변동이 섞인다.

단 **전제 자체는 살아 있었다** — 등급(`X_grade`)을 알고도 남는 `prizeCond` 조건부
엔트로피가 **1.568 / 3.889 = 40%** 다. 등급이 상대 수준을 다 설명하지 못한다.
그래서 텍스트 대신 **원장에서 상대의 실제 실력을 직접 집계**했다.
(`X_rating` 은 충전 46%(2014년경 시작)로 전 구간을 못 덮어 쓰지 않고 as-of 통산승률을 썼다.)

피처 2개 (`tools/build_extra_field.py`, 3패스 전부 emit → update):
  · `F1_faced_wr_avg5`  최근 5출전에서 **만난** 상대의 as-of 통산승률 평균 (자기 제외)
  · `F1_beaten_wr_avg5` 최근 5출전에서 **이긴** 상대(착순이 뒤인 말)의 평균
충전 87.5% / 85.4% · y_ord 상관 r=+0.02 (누수 점검 통과)

### 규약을 지켰다는 점

- 가설을 **먼저 말로 적고** 시작했다 (이 절과 H1 절 첫 문단)
- 형태를 **하나만 정하고** 갔다 (avg5 / best5 / faced / beaten). 여러 변형을 만들어
  제일 좋은 걸 고르지 않았다 — 그게 선택 누수다
- 한 번에 하나씩 (H1 → H2 → H1+H2)
- 구성은 원장 기준 as-of, **valid 로 어떤 통계량도 적합하지 않았다**
- 판정은 valid **쌍체**, test 미개봉
- 다중비교 보정까지 명시

## ★ train 내부 시간분할 CV — valid 를 더 쓰지 않고 확정했다 (2026-09-10)

**왜.** valid 1,254경주를 이 날 하루에 **약 25번** 측정했다(계열 16종×3시드, PCA 2종,
H1/H2/H1+H2, 앙상블, Benter2 6종). 게다가 **top-1 이 안 움직인 것을 보고 나서 logloss 를
보고했다** — 지표를 결과에 맞춰 고른 셈이다. 같은 자를 계속 쓰면 숫자가 좋아 보이는
쪽으로 흐른다.

**표본별 검정력** (효과 logloss −0.0128, 경주별 sd 0.1325 기준):

| 표본 | logloss SE | \|효과\|/SE | 판정 | top-1 SE |


fold 마다 학습량·시대가 다른 것이 상쇄된다.

1. **logloss 개선은 경계선이 아니라 압도적이다** — p=7.6e−18. 그리고 효과가 정확히
   가법적이다(−0.0035 + −0.0049 = −0.0084 vs 실제 −0.0080).
2. **top-1 은 "못 잰다"가 아니라 "최대 +0.6%p 다"** — CI [−0.01, +0.59]. valid 의
   [−0.88, +1.36] 보다 6배 좁다. 시장과의 격차가 6%p 인데 상한이 0.6%p 라
   **있어도 실용적으로 무의미하다.** 이건 애매한 결론이 아니라 **정밀한 영(null)** 이다.
3. **valid 가 낙관적이었던 것이 확인됐다** — logloss −0.0128 → −0.0080. 25번 측정한
   대가가 그만큼이다. 앞으로 valid 는 튜닝에만 쓰고 판정은 이 CV 로 한다.
