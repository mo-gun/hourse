## 2. 하루 돌리는 법

경마는 **금·토·일**이다. 날짜는 `--date YYYYMMDD`, 생략하면 오늘.

```bash
# ① 프레임 빌드 — 전날 밤이나 당일 아침. 3~4분
python raceday.py build --date 20260912

#    (선택) 누수 검증까지. 빌드를 2회 하므로 7~8분
python raceday.py build --date 20260912 --leakcheck

# ② 모델 학습 — 1~2분. 주 1회면 충분하지만 매일 해도 무방
python raceday.py train --date 20260912

# ③ 자동 예측 — 아침에 켜 두면 경주마다 T-10분에 알아서 발사한다
python raceday.py auto --date 20260912

# ④ 채점 — 경주 끝난 뒤 아무 때나
python raceday.py score --date 20260912
```

보조 명령:

```bash
python raceday.py status  --date 20260912                        # 편성·T-minus
python raceday.py predict --date 20260912 --meet 1 --race 3      # 한 경주만
python raceday.py predict --date 20260912 --meet 1 --race 3 \
       --odds "1:3.2 2:5.8 3:12.4 ..."                           # 배당을 직접 넣기
```

`auto` 는 **끊고 다시 켜도 안전하다** — 이미 예측한 경주는 로그를 보고 건너뛴다.

산출물은 전부 `out/` 에 떨어진다:
`_frame_<날짜>_fwd.parquet` (프레임) · `models/` (모델) ·
`live_pred_<날짜>.csv` (예측 봉인) · `scored_<날짜>.csv` (채점)

## 4. 배당(시장확률)은 실시간으로 얻을 수 없다

전수 확인했다. 추측이 아니다.

| 찾아본 곳 | 결과 |
|---|---|
| 오픈API 배당 5종 | 전부 "시행된 경주의 **확정**배당". 예정 경기 조회 **0행** |
| `race.kra.co.kr` `.do` 경로 73개 | 배당 페이지 없음 |
| `m.kra.co.kr` 경로 65개 + JS 번들 9개 | 배당 AJAX 엔드포인트 **0개** |
| `m.kra.co.kr/.../scoretableDailyList.do` | 일자별 **성적표**. 지난 개최일만 채워진다 |
| `korearace.com` | robots 는 허용이나 내용이 JS 렌더링 · 배당 없음 |
| `gumvit.com` | 전문가 예상 커뮤니티. "배당" 은 글 제목·순위표일 뿐 |
| **`onbet.kra.co.kr`** | **실시간배당 있음**(`RltmDvdndC`) · **비로그인 차단** |

`onbet` 의 자기 코드가 답이다:

```js
function commonNowRate(params) {   // 현재배당률 조회 공통함수
    //현재경주, 지난경주 페이지에서는 비로그인시 프로세스 중단.
```

**에뮬레이터로도 안 된다** — 벽이 "앱 전용"이 아니라 "로그인"이기 때문이다.

그리고 시행일에 **1,168회 관측**으로 확정했다 (`probe_odds_live.py`):
완주한 모든 경주에서 배당이 처음 보인 시점이 **T−5 ~ T+1분**이었다.

```
T-10분  API원장 0/7 · API배당 0행 · 웹 0쌍
T- 3분  0/7 · 0행 · 0쌍
T+ 2분  7/7 · 7행          ← 여기서 들어온다
```

**결과적으로 이게 방법론적으로는 깨끗하다** — 모델이 배당을 볼 방법이 없으니
누수가 원천적으로 불가능하다. 대신 시장과 5%p 격차를 안고 간다.

배당을 쓰고 싶으면 **사람이 onbet 에서 읽어 `--odds` 로 넣으면 된다.**
그러면 79피처 모델(73 + 마체중 2 + 시장 4)이 돈다.

## 5. 당일에 바뀌는 것 — 자동 반영한다

출전표는 D-1 에 굳히지만 **당일에 바뀐다.** 9/11 에 실제로 둘 다 발생했다.

| | 9/11 발생 | 처리 |
|---|---|---|
| 출전취소 | 2건 (제주 6R 아신 · 부경 7R 아리온태양) | **자동 반영** |
| 기수변경 | 1건 (제주 6R 8번마) | **경고만** (아래) |

원장은 취소마를 지우지 않고 **`ord` 센티널**로 표시한다(91·92·93·94·95·98·99 —
원장 전체의 2.22%). 예측 직전에 이를 읽어 취소마를 빼고 **경주 내 값을 다시 계산**한다:

```
X_dusu · X_gate_rel · F5_race_n_front · _z/_rk 26컬럼
```

안 하면 두수가 틀린 전제로 예측이 돈다.

> **기수변경은 완전히 처리하지 못한다.** 기수가 바뀌면 `F3_jk_*`(기수 승률 4개)를
> 다시 만들어야 하는데 as-of 누적 상태가 프레임에 없다. 값을 그대로 두고 **경고만
> 출력한다** — 조용히 틀린 값을 쓰는 것보다 낫다고 판단했다. **알려진 한계다.**

## 6. 결과를 읽는 법 — 이게 제일 중요하다

**한 경주, 하루로는 아무것도 판정할 수 없다.**

| 표본 | top-1 표준오차 |
|---|---|
| 1경주 | — |
| 16경주 (하루) | **±12%p** |
| 1,254경주 (valid) | ±0.85%p |

9/11 에 오전 3경주에서 **66.7%** 가 나왔다가 하루 끝에 **33.3%** 로 내려앉았다.
그 66.7% 는 정보가 아니라 잡음이었다.

**우승마가 우리 몇 픽이었나** (valid, 7~11두 1,014경주):

| | 확률 |
|---|---|
| **1픽** | **32.5%** |
| 2픽 | 19.5% |
| 3픽 | 14.1% |
| 4픽 이하 | 33.9% |

**설계상 3번에 2번은 1픽이 아닌 말이 이긴다.** "연속으로 틀렸다"는 느낌은
대개 이 분포의 정중앙이다. **1픽만 보지 말고 상위 3픽으로 읽어라** —
3픽 안에 우승마가 들 확률이 66% 다.

점수 격차도 같이 봐라. 상위 2두 점수 차가 0.1 안쪽이면 모델이 "혼전"이라고
말하는 것이다(9/11 부경 5R: 상위 4두가 0.23 안 → 우리 3픽이 우승).

## 8. 지키는 규칙 — 깨면 비교가 무효다

- **`game` 3,700경주는 학습·검증·평가 어디에도 쓰지 않는다.** 사용자가 플레이할 경주다
- **`test` 는 최종 1회.** 비교·튜닝은 `valid` 로 한다
- **정렬을 바꾸지 않는다.** `race_id` 연속 블록이고 LightGBM `group` 이 그 순서를 가정한다
- **시드 3개 이상** 평균±표준편차로 읽는다 (top-1 검출 한계 ±2.39%p)
- **집계는 대상 경주보다 엄격히 이전 행만** 쓴다
- 통산성적 API 필드는 "오늘 기준 스냅샷"이라 **그대로 쓰면 미래가 샌다**
  (목록은 `kra_client.LEAKY_FIELDS`)

## 11. 제품 연동 — 팀 DB·화면에 붙이는 계약 (2026-09-15)

모델이 팀 제품(front/back/DB)에 붙는 지점을 실측으로 확정했다. 상세는 정원님 레포
`basemodel/` 의 두 문서에 있다 — **[INTEGRATION.md]** 진단 · **[AI-CONTRACT.md]** 실행 명세.
(브랜치 `feat/basemodel-axis-ranker`)

```
점수  raw = Σ( groupWeights[k] × ax_k ) / 100        k = 6축
확률  p   = softmax( raw × 0.0445 ),  경주 안에서
적재  entry_feature_score 41칸 = ax_* 6(계산) + 표시 지표 35(화면)
```

### 온도 0.0445 는 그대로 쓴다 — 독립 측정 다섯 번
