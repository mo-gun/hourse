# 학습 데이터셋 규격 v1.0.0

> 팀원 6명이 **동일한 학습·검증·테스트 데이터**로 각자 다른 가중치 모델을 만들기 위한 계약.
> 기계가 읽는 단일 원천은 [`schema.py`](../schema.py). 이 문서는 그 이유를 설명한다.

---

## 1. 왜 이 형태인가 — 근거

| 설계 | 근거 |
|---|---|
| **경주 단위 그룹 키(`race_id`)** | Bolton & Chapman(1986), Benter(1994). 경마는 말을 독립적으로 평가하는 문제가 아니라 **한 경주 안의 상대 비교** 문제다. 일반 로지스틱은 경주 내 경쟁을 표현하지 못한다. conditional logit / LightGBM `lambdarank` 둘 다 그룹 배열을 요구한다 |
| **인기도를 별도 2단계로** | Benter의 2단계 구조 — 1단계에서 펀더멘털 강도를 뽑고, 2단계에서 공개배당률과 결합한다. 시장은 강력한 정보원이라 무시하면 손해, 그대로 쓰면 시장을 못 이긴다 |
| **구간기록을 기준기록 대비로 정규화** | `Pace figure = (Par − Actual) + Variant`. 경마장·거리·주로가 다르면 원시 초(秒)는 비교 불가. 서울/부산/제주가 **서로 다른 구간 컬럼**을 쓰는 문제도 이걸로 흡수한다 |
| **경주 레벨 페이스 압력 피처** | 선행마가 여럿이면 페이스가 빨라져 무너지고 추입마가 유리해진다. 말 단위 피처만으로는 이 상호작용이 안 잡힌다 |
| **as-of 롤링 집계 강제** | 이 프로젝트에서 이미 실측으로 확인된 누수 — API의 통산성적 필드는 *오늘 기준 스냅샷*이다 |

---

## 2. 그레인과 인덱스

**1행 = 말 1두 × 경주 1회.**

| 컬럼 | 역할 |
|---|---|
| `race_id` = `{rcDate}_{meet}_{rcNo}` | **그룹 키.** 랭킹 모델의 `group`, conditional logit의 조건부 단위 |
| `row_id` = `{race_id}_{chulNo}` | 행 고유키 |
| `rcDate` | 시간 분할 기준. 정렬은 항상 이 컬럼 |
| `hrNo` `jkNo` `trNo` | 말·기수·조교사 ID |
| `split` | `train` / `valid` / `test` — **6명이 이 컬럼을 그대로 쓴다** |

> 정렬은 반드시 `race_id` 기준으로 묶여 있어야 한다. LightGBM `group` 배열은 "연속된 N행이 한 그룹"이라고 가정하므로, 섞이면 조용히 틀린 모델이 나온다.

## 3. 타깃

| 컬럼 | 용도 |
|---|---|
| `y_win` | 1착 여부 — 이진 분류 |
| `y_plc` | 3착 이내 (7두 미만 경주는 2착 이내) |
| `y_rel` = `max(0, dusu - ord)` | **랭킹 라벨.** LightGBM `lambdarank` |
| `y_ord` | 착순 원값 |
| `y_speed_fig` | 스피드 지수 — 회귀 타깃 대안 |

**권장 기본형**: `objective="lambdarank"`, `label=y_rel`, `group=race_id별 두수`. 경주 내 상대 순서를 직접 최적화하므로 위 1번 근거와 맞는다.

## 4. 데이터 분할 — 6명 동일

```
train  2010-01-01 ~ 2024-12-31
valid  2025-01-01 ~ 2025-12-31
test   2026-01-01 ~          (동결)
```

세 가지를 지켜야 비교가 성립한다.

1. **시간 순서 분할, 셔플 금지.** 무작위 분할은 미래 경주로 과거를 예측하게 만든다
2. **경주를 쪼개지 않는다.** 같은 `race_id`가 두 세트에 걸치면 안 된다
3. **test는 최종 1회만.** 6명이 각자 튜닝하며 test를 열어보면 그 순간 test가 valid가 된다

시작점이 2010년인 이유: 조교·장제 데이터가 2010년까지 소급된다. 원장은 2000년부터 있지만 2000~2009 구간은 F1의 조교·장제 피처가 전부 결측이 되어 6개 축의 조건이 달라진다.

## 5. 피처 그룹 — 접두사가 곧 담당

접두사로 그룹을 구분해서, 가중치 적용이 문자열 필터 한 줄로 끝난다.

| 그룹 | 담당 | 전용 컬럼 | 핵심 내용 |
|---|---|---:|---|
| `X_` | **공통 — 전원 포함** | 14 | 연령·성별·거리·등급·게이트·두수·부담중량·휴양일수·레이팅·마체중 |
| `F1_` | 최근 성적 | 26 | 통산/365일 성적, 최근 3~5경주 착순·스피드, 등급 변동, **조교**(28일 횟수·시간·수영·강도변화), **장제**(경과일·형태변경) |
| `F2_` | 부모 성적 | 16 | 부마/모마/외조부 ID, 자마 승률·스피드, **혈통 거리적성**, **혈통 주로적성**, 전형제 성적 |
| `F3_` | 기수 실력 | 15 | 기수 통산/365일/경마장별/거리별 승률, 조교사 성적, **기수-말 조합**, 기수-조교사 조합 |
| `F4_` | 거리·날씨 | 15 | 거리대별 성적, 최적거리 이격, 거리 변화, 경마장 적성, **불량주로 성적**, 주로 함수율·날씨 |
| `F5_` | 주행 스타일 | 14 | 각질 4분류, 초/중/종반 상대위치, 순위 상승폭, 상3F, 게이트스피드, **경주 선행마 두수**, **페이스 압력** |
| `F6_` | 인기도 | 5 | 예상 시장확률, 예상 인기순위, **밸류 갭** |

```python
from schema import features, weights

cols = features(groups=["X", "F3"])   # 기수 실력 담당이 쓸 컬럼
w    = weights("F3", high=3.0)        # 자기 그룹만 3배, 나머지 1배
```

## 6. 가용 시점 티어 — 예측 시점이 곧 제약

2026-08-28 발주 시간대 실측([`probe_realtime.py`](../probe_realtime.py)) + 2026-09-10
마체중 재실측([`probe_wghr_raceday.py`](../probe_wghr_raceday.py)) 결과다.

| 티어 | 공개 시점 | 해당 컬럼 | 컬럼 수 |
|---|---|---|---:|
| **A** | D-1 확정 | 대부분 | 100 |
| **B** | 발주 **T-61~65분** | `X_wgHr` `X_wgHr_delta` (마체중) | +2 |
| **C** | 발주 **T-10분** | `F4_track_moist` `F4_track_state` `F4_weather` | +3 |

> **B 정정 (2026-09-10)** — 원래 "T-60~90분"이라 적혀 있었고, 그 숫자의 출처는
> `docs/주제기획` 의 **[추정]** 이었다(`experiments/README.md` §7 이 2026-09-07 에
> "발주 전에 채워지는가"를 미해결로 다시 열어 둔 것도 같은 이유). 이번에 제주에서
> 4R 이 채워지는 순간을 4분 간격으로 포착했다 — **T-65분 0/8 → T-61분 8/8.**
> 즉 **아래쪽 끝(T-60)은 원래 값이 맞았고 위쪽(T-90)은 근거가 없다.** T-61~65 로 적는다.
> 같은 시점 3R(발주 14:00)이 T-36분에 이미 7/7 이던 것도 같은 규칙이다.
> 마체중은 **D-1 에는 없다**(9/11~13 다가올 5건 423두 전부 0) 이므로 tier=A 가 아니고,
> 발주 전에는 있으므로 tier=G 도 아니다.
>
> ⚠ 이 티어를 실시간 모델에서 실제로 쓰려면 추론이 **각 경주 발주 T-60분 안쪽**에
> 돌아야 한다. 아침에 하루치를 한 번 돌리는 배치라면 뒤 경주는 결측이 된다.

`features(tier="A")`로 전날 예측 모델을, `tier="C"`로 발주 직전 모델을 만들 수 있다. **모델의 예측 가능 시점은 그 모델이 쓴 최고 티어가 결정한다** — 날씨를 한 컬럼이라도 쓰면 전날 예측은 불가능하다.

## 7. 누수 규칙 — 위반하면 성능이 거짓으로 좋아진다

**규칙 1. 모든 집계는 `(rcDate, rcNo)`가 대상 경주보다 엄격히 이전인 행만 사용한다.**
같은 날 앞 경주는 써도 되지만 같은 경주는 안 된다.

**규칙 2. API의 통산성적 필드를 그대로 쓰지 않는다.**
`rcCntT` `winRateT` `rcCnt` `winRate` `avgWinDist` `rankTop` 등은 **조회 시점 스냅샷**이다. 실측 근거: 같은 말(`0047543`)의 `rcCntT`가 2025-01 / 2025-07 / 2026-07 조회에서 전부 36으로 동일했다. 과거 경주 행에 붙이면 미래를 안 채로 예측하게 된다. 전체 목록은 `schema.FORBIDDEN_SOURCE_FIELDS`에 있고, 빌더가 결과물에 남아있지 않은지 검사한다.

**규칙 3. 이번 경주의 결과 계열은 전부 타깃 쪽이다.**
`ord` `rcTime` `diffUnit` `winOdds` `plcOdds`, 그리고 **이번 경주의 구간기록 전체**. F5는 반드시 *과거* 경주의 구간기록만 집계한다.

## 8. 구간기록 정규화 — F5의 전제

구간 컬럼이 경마장마다 완전히 다르고 상호 배타적이다.

| 경마장 | 컬럼 | 형태 |
|---|---:|---|
| 서울 | 7 + 7 | `se*AccTime`(누적시간) + `sj*Ord`(순위) |
| 부산경남 | 22 | `bu*` — G8f/G6f/G4f/G3f/G2f/G1f 누적시간·순위 + 구간별 소요시간 |
| 제주 | 7 | `je*Time` — 시간만, 순위 없음 |

**정규화 절차**

1. 4개 표준 지점으로 매핑 — `S1F`(초반1F) / `MID`(중반) / `G3F`(상3F) / `G1F`(마지막1F)
2. 시간만 있고 순위가 없는 경마장(제주)은 경주 내 시간 순서로 순위를 계산
3. 순위를 **상대위치**로 환산: `pos = (ord - 1) / (dusu - 1)`, 0=선두 1=최후미. 두수 차이를 흡수한다
4. 시간은 **기준기록 대비**로: `(경마장 × 거리 × 주로상태) 중앙값 - 실제기록`. Pace figure 공식과 같은 발상
5. 구간기록이 있는 과거 경주 수를 `F5_sect_n`으로 남긴다 — 표본이 적은 말의 F5 피처는 신뢰도가 낮으므로 모델이 가중할 수 있게

## 9. 팀원별 작업 방식

**F1~F5 담당 5명** — 동일 데이터, 동일 분할, 동일 타깃. 자기 그룹 가중치만 올린다.

```python
from schema import features, weights
import lightgbm as lgb

MY = "F3"                                   # 자기 그룹
cols = features(groups=["X", MY])           # 또는 전체 features() + 가중치
w    = weights(MY, high=3.0)
# LightGBM 은 컬럼 가중치가 없으므로 둘 중 하나:
#   (a) feature_contri 파라미터로 트리 분할 시 그룹 우대
#   (b) 자기 그룹 컬럼만 쓰기 (features(groups=["X", MY]))
```

**F6 인기도 담당 1명은 작업이 다르다.** 가중치를 올리는 게 아니라 **서브모델을 하나 더 만든다.**

1. `F6X_mkt_prob`(확정배당률 내재확률)를 **타깃**으로 하는 시장예측 모델을 학습
2. 그 예측값이 `F6_mkt_prob_pred` — 경주 전에 산출 가능하고 누수가 없다
3. 본 모델 확률과의 차이가 `F6_value_gap` = 시장이 저평가한 말

이게 Benter 2단계다. 공공 API가 **경주 전 배당률을 주지 않기 때문에**(발주 4분 전에도 0행임을 실측 확인) 실제 배당률을 입력으로 쓸 방법이 없고, 이 우회가 유일한 정공법이다.

## 10. 공통 평가 — 6명 동일 지표

같은 test 셋에서 아래를 전부 보고한다.

| 지표 | 의미 |
|---|---|
| Top-1 적중률 | 1위 예측이 실제 1착인 비율 |
| Top-3 적중률 | 1위 예측이 3착 이내 |
| NDCG@3 | 순위 품질 |
| 평균 예측 착순 | 낮을수록 좋음 |
| **vs 시장 베이스라인** | `F6X_mkt_rank == 1` 단순 베팅 대비 |

마지막 줄이 핵심이다. 시장(인기 1위마)을 못 이기면 모델의 의미가 없고, 이 프로젝트가 "정량 성과 측정 가능"을 내세운 근거이기도 하다.

## 부록 — 아직 안 된 것

- 데이터셋 실물은 아직 생성 전이다. 이 문서와 `schema.py`는 **규격**이고, 빌더는 다음 단계다
- 빌더가 해야 할 일: 원장 백필(2010~2026) → as-of 롤링 집계 → 조교·장제·혈통 조인 → 구간기록 정규화 → 분할 → parquet 저장
- `F6_mkt_prob_pred`는 서브모델 출력이라 2패스가 필요하다. 1패스로 기본 데이터셋을 만들고, 서브모델 학습 후 컬럼을 채운다
